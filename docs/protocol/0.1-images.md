# VVV 0.1 image capability draft

This experimental capability contract is implemented by the portable `skills/vvv` package in this repository. It is shared by Codex native tool handoff, the pinned local c2c adapter and an explicitly selected Images API. It does not define a remote authentication protocol or grant subscription access to other services.

The portable specification and examples are maintained with the installed Skill in [image-generation.md](../../skills/vvv/references/image-generation.md). The executable entry point is [vvv_image.py](../../skills/vvv/scripts/vvv_image.py).

The contract separates five facts: input intent, local provider prerequisites, actual generation, output-file validation and visual acceptance. In particular, a supported host, valid login or completed agent turn is not a generated asset. Generation succeeds only after the real image passes decode, background and requested-size checks. Review and scene integration remain agent responsibilities.

The request has version, ID, operation, prompt, ordered role-bearing references, background, size, format and explicit resize policy. The result supplies a unique project-local file, measured metadata and a provenance record. Raw output and original references remain available. Native and bridged subscription calls share these asset semantics with configured APIs; their authentication, capabilities and billing remain provider-specific.

The image helper accepts an explicitly selected existing project directory, including a custom composition without `vvv.json`. If that manifest is present, it must declare `vvvFormat: "1.0"` (or be a legacy `version: "0.1"` project). Image request and configuration documents keep their own `0.1` version. Assets and receipts are stored under the selected project's `public/` and `creative/`; custom projects integrate them through their own renderer. This does not convert a custom project into a VVV template project.

Provider discovery makes no network generation call. Native availability is declared only from the current tool surface. The c2c adapter checks the official CLI's login method and required command flags without reading credentials. An API route requires explicit selection and a locally supplied environment-variable credential. Failure never silently switches routes or retries a potentially billable image request.
